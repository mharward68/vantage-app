## What was done

**Finding 2 — the cursor artwork.** One CSS custom property, `--cursor-col-resize`, in `style.css` `:root`. A 24×24 inline SVG data URI: black glyph, white halo, hotspot `12 12`, with `, col-resize` as a mandatory keyword fallback. No new file, no build step. The stock Windows `col-resize` glyph is drawn with a mask and takes its colour from what is underneath, which is why it all but vanished on the light-purple header and was fine in dark; a black-on-white-halo bitmap does not depend on the background at all.

**Finding 3 — the mid-drag blink. TWO fixes, and the plan was right that either alone is a false pass.**

1. **The JS guard.** A module-scope `layoutResizeLive` boolean, set in the resize branch of `initHeaderDrag()` and cleared in its `onUp`. The thead `mousemove` returns early while it is true, so the handler stops wiping the inline cursor off the th the drag started on.
2. **The document-wide lock, which is the half that actually carries it.** `document.body.style.cursor = "col-resize"` was **replaced**, not supplemented, by `document.body.classList.add("layout-resizing")` plus a `body.layout-resizing, body.layout-resizing * { cursor: var(--cursor-col-resize) !important; }` rule. An *inherited* body cursor loses to any descendant that sets its own — which is the entire mechanism of Finding 3, because `.taskhub-sortable` sets `cursor: pointer` on every TaskHub header. The guard alone protects only the th the pointer started on and says nothing about the neighbour it crosses two frames later.

**One definition, two readers.** `app.js` holds `LAYOUT_RESIZE_CURSOR = "var(--cursor-col-resize)"` — a reference, not a second copy of the 692-character data URI. `var()` in an inline `style.cursor` was verified to resolve at runtime before anything was built on it.

## Assumptions logged this session

1. **THE CSS CUSTOM PROPERTY IS THE SINGLE DEFINITION AND `app.js` HOLDS ONLY A `var()` REFERENCE.** The alternative was a literal data-URI string in both files, because the `body.layout-resizing *` rule needs it in CSS regardless. Verified before relying on it: an inline `el.style.cursor = "var(--cursor-col-resize)"` computes to the full `url(…)` value.
2. **`document.body.style.cursor` WAS REMOVED, NOT KEPT ALONGSIDE THE CLASS.** So a future trace reading `document.body.style.cursor` mid-drag will see `(none)` where the 2026-09-01 review saw `col-resize`. That is the fix, not a regression — read `document.body.classList.contains("layout-resizing")` instead.
3. **THE `*` AND THE `!important` IN THE DRAG RULE ARE LOAD-BEARING AND SCOPED.** They are the only way to beat a descendant's own cursor rule during a gesture that has already left the element it started on, and they apply only while the class is on the body.
4. **24×24, NOT 32×32.** The plan set 32×32 as a ceiling, not a target. 24 keeps the glyph the same visual size as the system cursor it replaces and stays well under the size at which platforms silently refuse a cursor image.
5. **`.col-resize-handle` WAS NOT TOUCHED.** CampaignHub's older per-table resizer (`makeTableColumnsResizable()`, used by `email-accounts-table` and `domains-table`) is different machinery outside this session's compartment. It still uses the stock keyword cursor. **Phase backlog.**
6. **THE VERIFICATION MUTATED `state.columnLayouts` AND ROLLED IT BACK EXPLICITLY.** Resizing is the feature; it cannot be tested without writing widths.
