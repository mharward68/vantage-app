## What was done

Four things, all in the DATA/LOGIC compartment. **The app is left fully usable** and the live database is byte-for-byte where it started.

- **`prospectByEmail(email, excludeId = null)` — the P6 resolver, and the only one.** Case-insensitive and trimmed, matching what the import's dedupe key has always done. An empty email is never a duplicate (records without one exist, and `"" === ""` would collide every one of them). `excludeId` is the edit branch; without it a record reports itself.
- **`saveProspect()` checks on both branches, and it checks BEFORE `resolveCompanyByName()`.** That ordering is load-bearing and is commented as such: `resolveCompanyByName()` **creates a company record as a side effect** when the typed name is new, so checking after it would leave a stray company behind on every refused save. Verified — the refused probe typed a brand-new company name and `state.companies` stayed at 5.
- **`commitProspectField()`'s email path uses the same resolver and reverts.** On a duplicate the field is repainted from the stored value and the warning says "The field was put back." This is the one place the writer's repaint-only-what-changed rule cuts the other way: the user typed something the record does not hold, so leaving the input alone would show a value that was never saved.
- **Import skip-and-report — MOSTLY ALREADY EXISTED, and this is the finding that changed the session's shape.** `mergeImportedRecords()` has deduped prospects on `email:<lower>` and reported the count via `mergeSummaryLabel()` since before this phase. What was missing was getting the rows back out. Added: `skippedRecords` on that function's return (additive; the four other routes through it are untouched and none reads the new key), a `_srcCols` transient on each imported prospect carrying its **original** source row, and `#btn-download-skipped-rows` beside Import CSV/Excel — hidden until an import actually skips something, and hidden again the moment one runs clean.
- **The import keeps its own scan and shares only the normalisation.** Deliberate, and commented at the resolver so a later session does not "finish the job": `prospectByEmail()` cannot see two duplicate rows colliding **inside the same file**, and calling it per row is O(rows × prospects). `mergeImportedRecords()`'s running Set does both correctly. Both now call `normalizedEmail()`, so the two surfaces cannot drift into different definitions of "the same email" — which is the part that would actually hurt.
- **`state.taskSettings = { dateMode: "business" };` added to `wipeAllData()`'s explicit list**, beside `state.columnLayouts`, with the Phase 1 history in the comment. The literal matches `ensureStateDefaults()`'s default so a wipe leaves the store in the shape a first run does.
