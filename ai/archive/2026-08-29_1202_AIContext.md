## Assumptions made

- **The editor is a modal, not a form rendered inside the inspector.** Scope §4 says "inline in the inspector"; read as "does not navigate away", which the modal satisfies — the inspector stays behind it. C8 freezes exactly one `openTaskEditor()` serving both the inspector and (from 1.5) TaskHub, and a form living inside `#inspector-memberships` could not serve TaskHub without a second implementation. Ladder 1 and 3 both point the same way.
- **One `<input type="date">` covers "text entry and date picker"** — Chrome's date input is keyboard-typable and has a calendar. Reversible; a separate text field can be added if it reads wrong.
- **SCOPE AMENDMENT (Michael, mid-session 2026-08-29): the prospect is wired to the task, not chosen.** See the dedicated section below — this is a scope change, not an assumption.
- **`todayLocalDateStr()` instead of the file's usual `toISOString().split("T")[0]`.** That idiom is UTC: in America/New_York a task created after 8pm would be stamped tomorrow. DECLARATIONS stores local `YYYY-MM-DD`. Deviates from precedent on Ladder 1 (Stability) over Ladder 3.
- **Completion history is NOT logged here.** Setting status to Completed in the editor sets `completedDate` and nothing else. C5/history is Session 1.6; a comment in `saveTaskFromEditor()` says so. **A task completed in the editor between now and 1.6 will not appear in prospect history** — 1.6 should decide whether to backfill.
