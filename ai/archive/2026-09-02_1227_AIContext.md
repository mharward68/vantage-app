## Assumptions logged this session

1. **THE EXPANDED STATE IS NOT STORED ANYWHERE — NOT EVEN IN A MODULE-SCOPE VARIABLE.** It is a class on an element that `renderProspectDetailTabBody()` discards. So P9 ("no new persisted field, no new store") is satisfied *by construction* rather than by discipline, and "opens collapsed" is free. Step 4 of the trace is the proof. The plan's fallback if it must ever be remembered stands: it joins `state.columnLayouts` under its own key, never a new top-level store.
2. **THE CARD COLLAPSES, THE TAB DOES NOT.** The plan said "the Company tab opens collapsed" and named `.pd-company-card` / `.pd-company-grid` as the styling to touch. Collapsing the whole pane would hide the roster, which is the stated reason the tab exists. Reversible; if you want the roster folded too it is one more wrapper.
3. **THE DISCLOSURE HEADER CARRIES THE NAME AND INDUSTRY, so a collapsed card is not a mystery box.** The alternative — a bare "Company details ▸" row — was rejected on Ladder 2: it makes the user open the card to learn something the header could have told them.
4. **THE LISTENER IS DIRECT, NOT DELEGATED.** The button is created by `renderDetailCompany()` and dies with the container, exactly like the roster rows two lines below it. Delegation is for the *static* containers (`#prospect-detail-tabs`, the identity block) whose children are rebuilt under them.
5. **`.is-open` IS THE EXCEPTION AND COLLAPSED IS THE DEFAULT RULE**, deliberately that way round: if the class is ever lost the card fails **closed** with its header still readable, not open with the roster buried.
6. **A 3× CLONE OVERLAY REPLACED `computer.zoom` FOR THE MAGNIFIED SCREENSHOT.** `zoom` timed out twice on this machine (`Page.captureScreenshot` CDP timeout). The overlay clones the live element, so it is the real rendering scaled, not artwork. Removed and confirmed removed.
