## Assumptions logged this session

1. **`openInteractionModal()`'s new argument is TYPE-CHECKED, not defaulted.** 2B.3's tag-chooser precedent used `prospectId = state.selectedProspectId`. That shape does **not** work here: both existing call sites are `addEventListener("click", openInteractionModal)` **function references**, so they arrive with a `MouseEvent` as the first argument — which is not `undefined`, so a default never fires and the modal would target an Event object. One of those two sites is `#btn-aq-insp-add-interaction` in the **deferred AQ drawer**, which this phase may not touch. So the guard (`typeof prospectId === "string" && prospectId`) is what made the rehost possible **without entering the deferred surface or editing either listener**. DIRECTIVES §5: Gate-level — the alternative required touching a deferred surface, so it was eliminated before the ladder.
2. **`recordInteraction()` now uses `newHistoryId(p)`.** It minted `hist-${Date.now()}` directly while the app's other history writer already had a collision-safe minter. `deleteInteraction()` filters on `h.id !== histId`, so a duplicate id silently deletes every twin. Entry SHAPE unchanged; this only guarantees uniqueness within the prospect. Ladder rung 1 (Stability).
3. **One `style.css` syntax error was fixed in passing, and it was NOT mine.** Session 2B.3's identity-block comment had a **premature `*/` at what is now line 3865**, so the five lines after it were parsed as CSS and swallowed `#view-prospect-detail .detail-identity { padding: 4px 2px 0 }` as part of an invalid selector — the rule was being dropped entirely, with no error anywhere. One character. I fixed it rather than filing it because I was editing the same block and the whole block was about to grow. Logged rather than asked: reversible, and the alternative was appending to a file with a known broken comment in it.
4. **The three 2B.5 tabs are placeholders that RENDER, not `enabled: false`.** P4 freezes all six rows with those three `enabled: true`, so disabling them would put the strip out of step with the contract and would tell the user "this does not exist" rather than "not yet". Each returns a real element with a real one-line message.
5. **`renderDetailTasks()` keeps the re-parented subsection's own "Tasks" heading**, so there is a "Tasks" label inside a tab already called Tasks. That is the honest cost of a re-parent over a rewrite (the plan says *do not inflate it*), it is one line to remove, and it is on the Needs-your-eyes list rather than decided here.
